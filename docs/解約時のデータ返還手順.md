# 解約時のデータ返還・完全削除手順(T-17)

顧客(メディア運営者)との契約が終了したときに実行する手順。

**契約書に「解約時のデータ返還と完全削除」を明記している以上、この手順どおりに
実行できることが前提になる**(SPEC.md 12.2)。実行者はあなた(パッケージ提供者)。
運営者の管理画面には自己サービスの退会ボタンは置いていない。全会員の個人情報を
含む環境全体の破棄という操作の重大さに対して、Web からのセルフサービス操作は
リスクが高すぎるため、SSH 経由でのみ実行できるようにしている。

---

## 0. 前提

- 対象環境に SSH で接続できること
- `php artisan` が実行できること(パスは [Xserver実機調査手順](Xserver実機調査.md) を参照)
- 運営者側の解約合意が書面等で取れていること

---

## 1. データ返還(全データのエクスポート)

```bash
cd ~/(対象環境のパス)
php artisan data:export
```

- 掲載企業・事業所・求人・応募・会員の CSV(UTF-8 BOM 付き。Excel でそのまま開ける)と、
  ロゴ・事業所写真などのアップロード画像一式をまとめた ZIP を
  `storage/app/private/exports/{実行日時}.zip` に生成する
- 応募時点の履歴書スナップショット(`application_resume_snapshots.csv`)も含まれる。
  求職者が退会済みでも選考記録として残っているものはそのまま出力される
- 件数が多くてもチャンク処理のため実行時間・メモリの上限に達しない

### 1.1 ダウンロードして顧客へ渡す

```bash
# ローカル PC から scp で取得する例
scp <ssh接続先>:~/(対象環境のパス)/storage/app/private/exports/実行日時.zip ./
```

顧客へ渡す前に、必ず ZIP の中身を展開して各 CSV の件数が管理画面の表示件数と
一致することを確認する(完了条件: 「全データをエクスポートでき、中身が実データと
一致すること」)。

---

## 2. 完全削除

**エクスポートが完了し、顧客への返還が終わっていることを確認してから実行する。
取り消せない。**

```bash
php artisan data:destroy-all --admin=あなたの運営者メールアドレス
```

- `--admin` は必須。監査ログに実行者を記録するため、存在する運営者アカウントの
  メールアドレスを指定する(見つからない場合はエラーで停止し、何も削除しない)
- 実行すると削除対象の件数一覧が表示される
- **二段階確認**
  1. メディア名(サイト設定の `site_name`)を正確に入力する。一致しなければ中止
  2. 「本当に削除しますか?」に `yes` で答える。それ以外は中止
- 両方を満たすと実行前に `audit_logs` へ `data.destroy_all` を記録し、その後
  掲載企業・求人・応募・会員などの全データと、アップロード済みの全画像を削除する
- **資格・施設形態・職種などの製品マスタと `audit_logs` テーブル自体は削除しない。**
  マスタは顧客の個人情報を含まない配布データであり、消しても保護に寄与しない。
  `audit_logs` は「完全削除を実行した」という証跡そのものであり、全データを
  消した後もこれだけは読める必要があるため対象から外している

### 2.1 削除後の確認

```bash
php artisan tinker --execute="echo \App\Models\AuditLog::latest('id')->first()->action;"
# => data.destroy_all が表示されること
```

管理画面(`/admin/audit-logs`)にログインできる運営者アカウントも削除されている
ため、上記のように `tinker` で確認する。

---

## 3. 求職者個人の退会(参考)

契約解除とは別に、求職者本人がいつでも退会できる(マイページの「退会する」)。

- プロフィール・保有資格・職務経歴は削除される
- **応募時点の履歴書スナップショットは削除されない。** `applications.job_seeker_id`
  は `nullOnDelete` になっており、退会しても応募レコードとスナップショットは
  選考記録として残る(CLAUDE.md 3.6)。掲載企業からは「退会済みの応募者」として
  引き続き閲覧できる

---

## 4. 本番投入前に確認すること

- `ext-zip` が有効であること(`data:export` が ZIP 生成に使う。
  [Xserver実機調査手順](Xserver実機調査.md) の拡張モジュール一覧に含まれている)
- `storage/app/private` に十分な空き容量があること(画像を含む ZIP を一時的に
  ローカルディスクへ書き出すため)
