# デプロイ手順(T-18)

コードを更新したときに、既存の顧客環境へ配布する手順。
新規環境の立ち上げは [新規環境の構築手順.md](新規環境の構築手順.md) を参照。

**更新はステージング → デモメディア → 顧客環境の順に適用する**(SPEC.md 13.5)。
全顧客に一斉配布せず、検証が済んだものから順に配ることでリスクを分散する。

---

## 1. ローカルでの準備

```bash
# フロントに変更がある場合は必ずビルドしてコミットする
npm run build
git add public/build
git commit -m "..."

git push origin main
```

`public/build` は `.gitignore` から除外されており、git 管理下にある
(本番に Node.js が無いため。CLAUDE.md 4章)。**ビルドし忘れて push すると、
本番に古いフロント資産が配布される。**

---

## 2. 対象環境へのデプロイ

```bash
ssh <対象環境>
cd ~/app
./deploy.sh
```

`deploy.sh` は以下を順に行う([スクリプト本体](../deploy.sh)を参照):

1. メンテナンスモードへ切り替え(`php artisan down`)
2. `git pull origin main`
3. `composer install --no-dev --optimize-autoloader`
4. `php artisan migrate --force`
5. 設定・ルート・ビュー・イベントキャッシュの再構築
6. メンテナンスモードを解除(途中で失敗しても必ず解除される)

`chmod +x deploy.sh` が実行されていない場合は初回のみ実行しておく
(Windows で作成したファイルは実行属性が付かないことがある)。

---

## 3. デプロイ後の確認

- 対象ドメインにアクセスし、トップページが表示されること
- 更新した機能が反映されていること
- `storage/logs/laravel.log` に新規のエラーが出ていないこと(直近数分)
- [環境台帳.md](環境台帳.md) の「現在のバージョン」「最終デプロイ日」を更新する
  (バージョンは `git rev-parse --short HEAD` の値、またはタグ名)

---

## 4. ロールバック

デプロイ後に問題が見つかった場合。

```bash
ssh <対象環境>
cd ~/app

php artisan down --render="errors::503" --retry=15

git log --oneline -5           # 戻す先のコミットを確認
git checkout <直前の正常なコミット>

composer install --no-dev --optimize-autoloader
php artisan migrate:rollback --force   # 今回のデプロイでマイグレーションを実行した場合のみ
php artisan config:cache
php artisan route:cache
php artisan view:cache

php artisan up
```

マイグレーションのロールバックはデータを失う可能性があるため、
**先に `data:export` 相当のバックアップ(またはこの手順3章のバックアップ)が
直近に取れていることを確認してから実行する。**

---

## 5. 複数環境への一斉展開

環境が増えてきたら、[環境台帳.md](環境台帳.md) に列挙した環境へ順にこの手順を繰り返す。
台帳の「現在のバージョン」を見て、まだ更新していない環境を取りこぼさないようにする。
